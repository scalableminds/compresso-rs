# compresso-rs

[![crates.io](https://img.shields.io/crates/v/compresso-rs.svg)](https://crates.io/crates/compresso-rs)
[![docs.rs](https://docs.rs/compresso-rs/badge.svg)](https://docs.rs/compresso-rs)

A pure Rust implementation of **Compresso**, a lossless codec for 3D
segmentation (label) volumes from connectomics:

> B. Matejek, D. Haehn, F. Lekschas, M. Mitzenmacher, H. Pfister.
> *Compresso: Efficient Compression of Segmentation Data for Connectomics.*
> MICCAI 2017. [doi:10.1007/978-3-319-66182-7_89](https://doi.org/10.1007/978-3-319-66182-7_89)

The crate reads and writes the stream format of the
[`compresso`](https://github.com/seung-lab/compresso) Python package (stream
formats 0 and 1, magic `cpso`). Neuroglancer precomputed volumes with
`"encoding": "compresso"` use the same format.

- **Byte-identical to Python:** `compress` produces exactly the bytes of
  `compresso.compress`, and `decompress` returns exactly the labels of
  `compresso.decompress`. See [Compatibility](#compatibility).
- **Pure Rust:** no C/C++ toolchain, no `unsafe` (`#![forbid(unsafe_code)]`) and
  no runtime dependencies.
- **Safe on untrusted input:** malformed or corrupt streams return an `Error`.
  They never panic or read out of bounds.
- **Fast:** about 1–1.9 GB/s on real connectomics volumes, faster than the
  Python package's C++ extension (see [Performance](#performance)).

```toml
[dependencies]
compresso-rs = "0.1"
```

The library is imported as `compresso`.

## Usage

```rust
use compresso::{compress, decompress, CompressOptions, Connectivity, Header};

fn main() -> Result<(), compresso::Error> {
// A 3D volume in Fortran order: x varies fastest, then y, then z.
let shape = [64, 64, 8];
let volume: Vec<u64> = (0..64 * 64 * 8u64).map(|i| (i % 64) / 20 + 100 * (i / 4096)).collect();

// Same defaults as `compresso.compress(volume)` in Python:
// steps (4, 4, 1) with fallback to (8, 8, 1), 4-connectivity, random access z index.
let stream = compress(&volume, shape, &CompressOptions::default())?;
assert_eq!(decompress::<u64>(&stream)?, volume);

// compresso.compress(volume, steps=(8, 8, 1), connectivity=6)
let options = CompressOptions::default()
    .steps([8, 8, 1])
    .connectivity(Connectivity::Six);
let stream = compress(&volume, shape, &options)?;

// Inspect the header before decoding untrusted input: a tiny stream can
// declare a very large volume.
let header = Header::parse(&stream)?;
assert!(header.nbytes() <= 1 << 30);
Ok(())
}
```

| Python                                     | Rust                                                    |
|--------------------------------------------|---------------------------------------------------------|
| `compresso.compress(arr, steps, connectivity, random_access_z_index)` | `compress(&labels, shape, &CompressOptions { .. })` |
| `compresso.decompress(buf)`                | `decompress::<T>(&buf)` or `decompress_bytes(&buf)`      |
| `compresso.decompress(buf, z=(start, end))`| `decompress_z_range::<T>(&buf, start..end)`              |
| `compresso.header(buf)`                    | `Header::parse(&buf)`                                    |
| `compresso.labels(buf)`                    | `labels(&buf)`                                           |
| `compresso.remap(buf, mapping, preserve_missing_labels)` | `remap(&buf, \|label\| mapping.get(&label).copied(), preserve)` |
| `compresso.valid(buf)`                     | `valid(&buf)`                                            |

Labels can be `u8`, `u16`, `u32` or `u64`. NumPy `bool` arrays are encoded as
`u8`. For an array `arr` of shape `(sx, sy, sz)`, the Rust slice is
`arr.ravel(order="F")`.

`decompress_bytes` returns little-endian bytes for any label width, which
is useful when the width is only known at runtime (e.g. in a Neuroglancer
chunk reader).

## Compatibility

This crate is tested against `compresso` 3.3.3 from PyPI. The stream format
has not changed since 3.0. The tests cover:

- **343 checked-in reference streams** (`tests/fixtures`) generated by Python.
  For each one, the test decodes the stream and compares the output with
  Python's (full and z-range decodes). Then it re-encodes the decoded volume
  and requires the exact Python bytes. The cases cover all label widths,
  steps from 1×1×1 to 8×8×1, 4×4×4 and non-power-of-two steps, both
  connectivities, format versions 0 and 1, every z index byte width, labels
  around the literal escape threshold, long zero runs, empty volumes, and the
  automatic `(8, 8, 1)` fallback when 16-bit windows overflow.
- **Randomized differential runs.**
  `tools/generate_fixtures.py --random N` generates any number of random
  cases. 5,000 were verified during development. CI runs a fresh randomized
  batch.
- **Real connectomics data.** The two volumes that ship with the Python
  package (512³ `uint32` and `uint64`) were checked byte for byte in 5
  configurations each.
- Corrupted and truncated streams, which must fail cleanly.

### Differences from the Python package

All valid streams decode identically. The remaining differences only affect
input that Python itself does not handle:

- **Malformed streams** that make the C++ decoder read out of bounds (corrupt
  tables, missing locations, out-of-range window indices…) return an `Error`.
- **Dimensions above 65535** are rejected with `Error::DimensionTooLarge`.
  Python silently truncates them in the 16-bit header fields and writes an
  undecodable stream.
- **`labels` and `remap`** handle windows of ≤ 8 voxels (e.g. `steps=(2, 2, 1)`)
  correctly. Python reads their window table with the wrong integer width.
  Python's `remap` can also fail for format 1 streams whose tail is not a
  multiple of the window width.
- **`remap`** can map a label above `MAX - 7` even where it is stored inline.
  The entry is rewritten as a literal escape and the header and z index are
  adjusted. Python raises an `OverflowError` there.
- **`valid`** returns `false` for unsupported format versions instead of raising.

## Performance

Single-threaded, Apple M2 Pro, on the two 512³ volumes that ship with the
Python package (default options, i.e. steps 4×4×1 and format 1):

| volume                    | ratio | encode (Rust / Python) | decode (Rust / Python) |
|---------------------------|------:|-----------------------:|-----------------------:|
| `connectomics.npy` u32    | 48.8× | 0.35 s / 0.83 s        | 0.44 s / 0.83 s        |
| `ws.npy` u64 (watershed)  | 11.6× | 0.84 s / 4.39 s        | 0.81 s / 1.39 s        |

Decoding a z range with the random access index costs about 5 ms per slice
for these volumes. Run `cargo run --release --example bench` to reproduce
these numbers.

## How Compresso works

1. A voxel is a *boundary* voxel if its label differs from its +x or +y
   neighbor (or its +z neighbor with 6-connectivity).
2. The boundary map is cut into windows of `steps` voxels (4×4×1 by default).
   Each window becomes a bit mask (`u8`…`u64`). The distinct masks are
   stored once, and the sequence of mask indices is run-length encoded.
3. The non-boundary voxels form connected components. These are numbered in
   raster order, per z slice with 4-connectivity and over the whole volume
   with 6-connectivity. One label is stored per component.
4. Most boundary voxels take the label of an already decoded neighbor. The
   rest get an *indeterminate location* instruction: copy a specific
   neighbor, or a literal label.
5. Format 1 appends a per-slice index of component and instruction counts, so
   z slices can be decoded independently (`decompress_z_range`).

The [Python package's README](https://github.com/seung-lab/compresso#readme)
documents the format in detail.

## Development

```sh
cargo test                      # unit, fixture and robustness tests
cargo run --release --example bench -- volume.raw 8 512 512 512

# Regenerate the reference fixtures, or run a randomized differential test
# against the Python package (requires uv):
uv run --no-project --python 3.12 --with compresso==3.3.3 --with numpy==2.3.4 \
    python tools/generate_fixtures.py --output tests/fixtures
uv run --no-project --python 3.12 --with compresso==3.3.3 --with numpy==2.3.4 \
    python tools/generate_fixtures.py --output /tmp/cpso --random 2000 --seed 1
COMPRESSO_FIXTURES=/tmp/cpso cargo test --release --test fixtures
```

The minimum supported Rust version is 1.85.
